# Сповіщення, нагадування, push

## Один вхід
Усі сповіщення йдуть через `notifications/notify.service` → запис у стрічці + push через `push/dispatcher` (web, FCM, APNs). Ніхто інший не пише в стрічку і не шле push.

## Канали (ADR-0010)
- Зовнішній канал лише один — **web push**. Пошту, месенджери, SMS не додаємо без нового ADR.
- Стрічка в застосунку — джерело правди: вона отримує запис завжди, навіть коли push вимкнено.
- Підписку браузера оновлює клієнт після кожного входу (`syncWebPush`) і service worker за `pushsubscriptionchange`; сервер робить upsert за endpoint.
- Дозвіл на сповіщення запитується лише у відповідь на дію людини (кнопка) — інакше iPhone відмовляє.
- Продакшен: тільки HTTPS; ключі VAPID — з оточення, генеруються один раз (`npm run vapid`) і не змінюються.

## Отримувачі
- Одна функція `stakeholders(task)`: автор, контролер-користувач, той, хто зареєстрував контроль, виконавці. Ініціатор дії не отримує сповіщення про власну дію. Дублікати прибираються.
- Стрічка в застосунку отримує запис завжди; push — лише якщо тип не вимкнено людиною і зараз не «тихі години».

## Нагадування (ADR-0004)
- Чиста функція `reminders/plan.ts` вирішує, кому що нагадати; `runner.ts` завантажує дані, пише журнал нагадувань і надсилає. Логіку змінюємо в `plan.ts` + тести.
- **Інтервал по контрольних**: завдання → особистий → загальний (перший заданий виграє).
- **Попередження про термін**: пороги з налаштувань; поріг рахується лише якщо його перетнули після `deadlineSetAt`; за раз — одне попередження з найменшим порогом; текст показує **фактичний** залишок.
- **Прострочення**: виконавцям, автору, контролеру-користувачу, тому, хто реєстрував контроль; повтор — за налаштуванням.
- Будь-яке нагадування по контрольному завданню скидає і таймер контролю — щоб не було двох push одночасно.
- **Тихі години й вихідні** відкладають нагадування, але не губять його. Терміновий пріоритет ігнорує тихі години (налаштування).
- «Відкласти на 2 год» — `Snooze` на пару (завдання, людина).
- Один прохід одночасно: `pg_try_advisory_lock` — безпечно для кількох процесів.
- Спершу журнал нагадувань, потім push — збій push не повинен давати повторів щохвилини.

## Push
- Web Push (VAPID): Android Chrome, комп'ютер; iPhone — лише після «На екран Домів» (iOS 16.4+).
- Android-застосунок: FCM HTTP v1; канали `tasks` і `urgent` створює застосунок; `channel_id` у повідомленні має збігатися.
- iOS-застосунок: APNs напряму (ключ .p8, JWT ES256, оновлення 20–60 хв); токен із прапором `sandbox` для збірок розробника.
- Недійсний токен (`410`, `Unregistered`, `BadDeviceToken`, FCM `UNREGISTERED`) видаляється.
- На кожен виклик — тайм-аут; помилка push логується і не ламає дію користувача.
- **Вміст payload** (ADR-0005): назва завдання дозволена рішенням власника; жодних описів, коментарів, персональних даних понад ПІБ контролера.
- Telegram і подібні канали не використовуються (обмеження НКЦК від 20.09.2024).
