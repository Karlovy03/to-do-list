# CLAUDE.md — «Контроль», планер доручень

Простий планер для керівника: ставити завдання, брати їх **на контроль** (контроль може поставити й особа без акаунта), стежити за ходом виконання і отримувати push на телефон (нове завдання, контроль, термін спливає, нагадування по контрольних кожні N годин). Без гейміфікації та зайвого.

- **server/** — Express 5 + Prisma 6 (PostgreSQL) + zod 4, TypeScript. Зовнішній канал сповіщень — лише Web Push (VAPID, ADR-0010); код FCM/APNs є, але не використовується, поки немає застосунків.
- **client/** — React 19 + Vite + TanStack Query + react-router, CSS Modules. Той самий код збирається в застосунки Android та iOS через Capacitor 7.
- Інтерфейс **лише українською**, **одна світла тема**, затверджений дизайн МВС (ADR-0014: офіційний знак, Montserrat, «Токени МВС»).

## Неперемовні правила

1. **Архітектура модулів.** Сервер: `routes → controller → service → repository`. Prisma — лише в `*.repository.ts`. Права — лише в `*.policy.ts`. Клієнт: `component → hook → api`. Модулі спілкуються лише через `index.ts`-барель. → скіл **following-project-conventions**.
2. **Жодного великого файлу.** Ліміт 300 рядків; ділити за відповідальністю, а не за кількістю. Ворота: `npm run check:size`.
3. **Тексти — лише в YAML** у теці `texts/` свого модуля, кількома файлами за змістом. У коді — лише ключі. Ворота: `npm run check:texts`. → скіл **writing-ui-texts**.
4. **Стилі** — токени в `client/src/styles/base/`, кожен компонент має свій `X.module.css` поруч. Жодних кольорів/розмірів поза токенами, жодного спільного «великого» CSS. → скіл **styling-components**.
5. **Права перевіряє сервер**, у сервісі через policy. Невидиме завдання → `404`, а не `403`. Інтерфейс лише ховає кнопки — це не захист.
6. **Час — Europe/Kyiv**, через спільні помічники (`core/time.ts`, `shared/lib/time.ts`).
7. **Схема БД змінюється лише міграцією** (файл у `server/prisma/migrations`), ніколи `db push`.
8. **Без `any`**; невідоме — `unknown` + перевірка.
9. **Дизайн спершу у Figma (ADR-0015).** Новий екран чи зміна вигляду — макет у Figma, погодження власника, лише потім код клієнта.

## Скіли (`.claude/skills/`) — джерело правил

| Скіл | Коли |
|---|---|
| following-project-conventions | будь-який нетривіальний код, де покласти файл |
| writing-ui-texts | будь-який текст, що бачить людина |
| styling-components | будь-яка зміна вигляду |
| working-on-tasks-and-control | стани завдання, контроль, права, журнал |
| working-on-notifications | сповіщення, нагадування, push |
| working-on-events-and-calendar | заходи, календар, ящірка «Виконано!» |
| working-on-absences | відсутності, «В строю», «не турбувати», попередження під час доручення |
| working-on-live-updates | живі оновлення: потік /api/live, хто отримує сигнал, де публікувати, перечитування на клієнті |
| building-mobile-apps | Capacitor, Android/iOS, нативний push |
| writing-tests | будь-який тест; зміни прав — з негативними тестами |
| running-dev-workflow | команди, міграції, ворота перед комітом |

**Доктрина скілів:** скіл містить правила, процедури й інваріанти — **ніколи не знімок стану коду** (переліки багів, розміри файлів, лічильники). Кожна команда в скілі виконана під час написання і перевірена на позитивному (має знайти) і негативному (не має знайти) контролі.

## Рішення і ідеї

- `docs/decisions/` — ADR. Змінити записане рішення можна лише новим ADR, що його заміняє.
- `docs/IDEAS.md` — ідея, помічена під час задачі, записується туди і **не реалізується** в поточній задачі.

## Стиль роботи

- Спершу дослідити (код, рішення, зовнішні факти) і погодити план; для інтерфейсу — ще й макет у Figma (ADR-0015); потім писати код.
- Нічого понад задачу; без захисного коду для неможливих випадків; коментарі — лише «чому».
- Перед комітом — ворота з **running-dev-workflow**. Секрети (`.env`, ключі push) не комітяться.
