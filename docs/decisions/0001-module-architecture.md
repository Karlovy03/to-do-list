# ADR-0001: Модульна архітектура з шарами

- Статус: прийнято · 2026-11-25

## Контекст
Перша версія сервера мала один файл маршрутів завдань на 500+ рядків, де HTTP, права, Prisma і сповіщення були змішані; стилі клієнта — один файл. Власник вимагає архітектуру, як у професійних команд, без великих файлів. Досвід NPU: файли понад 1000 рядків і паралельні реалізації одного поняття були головним джерелом помилок.

## Рішення
- Сервер: модулі `modules/<m>/` із шарами routes → controller → service → repository; права — `*.policy.ts`; спільне — `core/`.
- Клієнт: feature-модулі `modules/<m>/` (api, hooks, components, pages, texts), спільне — `shared/`, оболонка — `app/`.
- Ліміт 300 рядків на файл; ворота `npm run check:size` у CI.
- Модулі спілкуються лише через `index.ts`.

## Наслідки
Більше файлів, але кожен читається окремо; зміна прав чи нагадувань локалізована й тестується без бази. Правила — у скілі following-project-conventions.
