# ADR-0005: Вміст push-сповіщень

- Статус: прийнято (рішення власника, ризик прийнято свідомо) · 2026-11-25

## Контекст
Push іде через сервери Apple і Google (APNs, FCM, Web Push). Безпечніше передавати лише номер і тип події; власник обрав зручність — показувати назву завдання.

## Рішення
- Payload: тип події, № і **назва** завдання, термін; посилання `/tasks/:id`.
- Ніколи не передаємо: опис, коментарі, підставу контролю, телефони, інші персональні дані.
- Формування тексту — в одній функції `notify.service`, щоб режим «лише номер» можна було ввімкнути одним налаштуванням без переробок.
- Відповідальність за зміст назв завдань — на власнику системи.

## Уточнення власника · 2026-11-26
- Посилання в payload — `/t/:id` (так влаштовані маршрути клієнта), а не `/tasks/:id`.
- ПІБ виконавця й коментарі в push не передаються; хто виконав — лише в стрічці застосунку (функція `pushPayload` у `notify.service`).

## Доповнення · 2026-11-27 (заходи, ADR-0016)
- Push про захід: вид події, **назва** заходу, дата й час початку; посилання `/events/e/:id`. Для видаленого заходу — без посилання.
- Опис заходу, список учасників і причину скасування push не передає — лише стрічка застосунку.
