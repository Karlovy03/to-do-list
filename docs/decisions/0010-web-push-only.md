# ADR-0010: Єдиний зовнішній канал сповіщень — web push

- Статус: прийнято · 2026-11-26
- Доповнює ADR-0008 (нативний push лишається в коді, але не використовується, поки немає застосунків)

## Контекст
Власник хоче безкоштовні сповіщення на телефон, які надійно доходять, без встановлення окремих застосунків.
Розглянуто:
- **Пошта (Gmail)** — затримки, ризик «Спаму», добові ліміти надсилання; часті нагадування неможливі.
- **ntfy** — надійний на Android, але кожному треба встановити окремий застосунок і підписатися; для iPhone однаково потрібен публічний сервер ntfy.sh.
- **Telegram-бот** — обмеження на службових пристроях органів влади та сектору безпеки (рішення НКЦК/РНБО, вересень 2024).
- **Signal** — офіційного API для ботів немає; неофіційний клієнт ламається від змін сервера, номер можуть заблокувати.
- **Нативні застосунки (FCM/APNs)** — окрема велика робота; для iPhone — платний акаунт Apple.

## Рішення
- Зовнішній канал один: **web push (VAPID)** через `notify()` → `push/dispatcher`. Пошти, месенджерів і SMS немає.
- Стрічка й лічильник у застосунку отримують усе завжди — це запасний канал на випадок, коли push вимкнено.
- Надійність забезпечуємо так: `urgency: high`; підписка оновлюється на сервері після кожного входу і за подією `pushsubscriptionchange`; мертві підписки (404/410) прибираються; після входу людина бачить підказку увімкнути сповіщення, на iPhone — інструкцію «На екран «Додому»».
- Продакшен: лише HTTPS, ключі VAPID генеруються один раз (`npm run vapid`) і ніколи не змінюються — інакше пропадуть усі підписки.

## Наслідки
- На iPhone сповіщення працюють лише з iOS 16.4+ і лише для застосунку, доданого на екран «Додому».
- Доставку не гарантує жоден канал: вимкнений дозвіл або жорстка економія заряду затримують push. Тому стрічка в застосунку — джерело правди.
- Пошта і ntfy записані в `docs/IDEAS.md` як можливі запасні канали.
