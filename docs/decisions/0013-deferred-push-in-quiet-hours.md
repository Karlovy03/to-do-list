# ADR-0013: Push про нове завдання і контроль у тихі години відкладається, а не губиться

- Статус: прийнято (рішення власника) · 2026-11-26
- Доповнює ADR-0004 (там «відкладають, але не губить» стосувалося лише нагадувань)

## Контекст
Аудит показав: подія, що сталася в тихі години людини (керівник увечері доручив завдання), потрапляла лише в стрічку — push не надходив ні тоді, ні зранку. Людина могла дізнатися про нове завдання лише відкривши застосунок.

## Рішення
- Push про **нове завдання** (`ASSIGNED`) і **постановку на контроль / зміну умов** (`CONTROL_ON`, `CONTROL_CHANGED`) у тихі години позначається `Notification.pushDeferred` і надсилається, щойно тихі години людини скінчаться (прохід нагадувань раз на хвилину).
- Решта подій (коментар, хід, частка «Виконано»…) у тихі години — лише в стрічці, як і раніше.
- Запис у стрічці з'являється одразу завжди.
- Перед надсиланням позначка знімається (як журнал нагадувань: збій push не дає повторів). Якщо завдання вже закрите, сповіщення прочитане або людину вимкнено — push не надсилається.
- Вимкнений людиною тип сповіщень не відкладається.

## Наслідки
- О 08:00 людина може отримати кілька push одразу — це очікувано.
- Тіло відкладеного push береться з запису стрічки, тому для цих подій у стрічку не додаються коментарі чи ПІБ (ADR-0005).
